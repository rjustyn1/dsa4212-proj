\section{Background and Related Work}
\label{sec:background}

\subsection{Adam and Shampoo-style optimizers}

Adam adapts the step size of each weight using running averages of its gradient
and squared gradient \cite{kingma2015adam}, and AdamW adds weight decay, which
shrinks the weights slightly at every step \cite{loshchilov2019adamw}. Because
Adam treats every weight on its own, it ignores how the weights in a matrix
interact. Shampoo uses this structure: for each weight matrix, it keeps two
small matrices that track how the gradient varies along the matrix's rows and
along its columns, and it uses them to rescale the update
\cite{gupta2018shampoo}. SOAP showed that Shampoo is closely related to running
an Adam-like method in a rotated coordinate system, given by the eigenvectors of
these two matrices, and it does exactly that: it rotates the update into this
coordinate system, rescales each coordinate as Adam would, and rotates back,
recomputing the rotation only occasionally to save time \cite{vyas2025soap}.
Its one-sided variant rotates only the shorter side of each matrix, which
further reduces the cost \cite{vyas2025soap}.

\subsection{Muon}

Muon takes a different approach. For each hidden weight matrix, it computes a
momentum update, a running average of recent gradients, and replaces it with
the nearest orthogonal matrix \cite{jordan2024muon}. This keeps the directions
of the update but makes it equally strong in all of them, so that no single
direction dominates. Computing the nearest orthogonal matrix exactly is
expensive, so Muon approximates it with five steps of the Newton--Schulz
iteration, a short sequence of matrix multiplications. Embeddings, the output
layer, and other small parameters are still trained with AdamW. The Muon
description is a technical note with reference code rather than a peer-reviewed
paper; we cite it as the definition of the method. Moonlight later showed that
Muon works for large language models when weight decay is added and each update
is rescaled to the typical size of an AdamW update \cite{liu2025muon}. This
version, Moonlight Muon, is our baseline.

\subsection{Combining and comparing optimizers}

Because SOAP and Muon change different parts of the update, they can be
combined, and public reference code already does so \cite{vyas_soapmuon_code}.
Comparing optimizers fairly is difficult, however. Wen et~al.\ found that many
reported speedups shrink when the baseline is tuned as carefully as the new
method, and that comparisons made partway through training can mislead because
the ranking of two optimizers can change later in training
\cite{wen2025fantastic}. We therefore tune both optimizers in the same way, test
them on seeds not used for tuning, and report the whole loss curve as well as
the final loss.
