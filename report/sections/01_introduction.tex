\section{Introduction}

Training a language model means repeatedly adjusting its weights to reduce its
prediction error, and the optimizer decides how each adjustment is made. Most
models are trained with AdamW \cite{kingma2015adam,loshchilov2019adamw}, which
treats every weight separately. Two recent optimizers instead use the fact that
most weights in a Transformer \cite{vaswani2017attention} are arranged in
matrices. Muon makes each matrix update equally strong in all directions
\cite{jordan2024muon}, and Moonlight showed that it scales to large language
models \cite{liu2025muon}. SOAP rescales each update in a coordinate system
learned from past gradients \cite{gupta2018shampoo,vyas2025soap}. Because the
two methods change different parts of the update, it is natural to ask whether
they can be combined: does adding SOAP's rescaling step make Muon train better?

We answer this question with a controlled experiment on a small GPT-style
model. The baseline is Moonlight Muon. The treatment, which we call
SOAP--Muon, adds SOAP's rescaling step before Muon's update in the MLP layers
and changes nothing else. Both optimizers use the same model, data, training
length, and learning rate, and every comparison runs both optimizers from the
same random seed, so any difference comes from the added step. We tuned the
learning rate of both optimizers in the same way on separate runs and then
compared them on five new seeds, training each model on 200M tokens.

Our main findings are as follows.
\begin{itemize}
\item SOAP--Muon learns faster early in training: for every seed, its
  validation loss is lower during the first 40M tokens. The lead is small,
  however. At its peak, it is worth about 1.5M tokens of extra training, and it
  disappears by about 80M tokens.
\item Over the whole run, the early lead and a later deficit almost cancel, so
  the main measure, the average validation loss during training, differs by
  only 0.034\%. At the end of training, SOAP--Muon is slightly worse for every
  seed, and it trains 2.37\% more slowly.
\item Tuning matters more than the optimizer change. An earlier comparison, run
  before the baseline's learning rate was properly tuned, favored SOAP--Muon
  for every seed. Proper tuning improved the baseline's final loss about four
  times as much as SOAP--Muon changes it and removed most of the advantage.
\item Repeating a single run on a different GPU changed its final loss by
  almost as much as the effect of SOAP--Muon, which limits how small an effect
  five seeds can detect.
\end{itemize}
